# Stage 3 新コードの環境確認キット v0.1

固定済み binding-001 を、指定検証器のあるローカル環境で確認するキットです。配布時点でWindowsの確認は未実行です。API呼び出し、パッケージ導入、GitHub Actionsは行いません。`execution_ready=false` のままです。

## 操作

1. ZIPを右クリックし「すべて展開」します。ZIPの中から直接起動しないでください。
2. 展開先の `run-environment-check.cmd` をダブルクリックします。
3. 終了画面に表示された結果ZIPを渡してください。成功でも失敗でも同じです。

既定では、003で記録された `local-preparation-20260930T102507Z-5db00b37` の `Scripts\python.exe` を使います。仮想環境の再有効化は不要です。場所が変わった場合は、コマンドプロンプトで次のように、実際のPythonを指定します。

```bat
run-environment-check.cmd "C:\実際の場所\Scripts\python.exe"
```

Python自体が見つからない場合は画面で停止します。この場合は検査も結果記録も始まっていません。スクリプトを起動できた場合は、検証器が未導入でも失敗を新規ZIPに保存します。検証器は `jsonschema==4.26.0` / `Draft202012Validator` に限り、自動導入や構造確認への切替はしません。別のPythonを指定した場合は、その実環境を記録し、003と同じ環境だったことにはしません。

結果はキットの隣の `stage3-environment-check-results` に、新しいIDのフォルダーとZIPで作ります。同じIDは再利用せず、キット内、参照リポジトリ内、既存結果へ書きません。UTF-8設定は子プロセスにも渡します。

## 読み方

検証器のimport・版確認の後、同じ実行ファイルで固定版 `tests/offline_checks.py` の通常経路を呼びます。4スキーマの確認と新コードの模擬入力・提案・状態・判定の検査を行います。モデル出力は取得しません。模擬応答は `offline_transport_fixture` として扱い、実モデル出力に読み替えません。

この通常経路は68項目です。以前の69項目には構造確認専用の1項目が含まれます。件数差は固定コードの条件分岐によるもので、試験の削除ではありません。003の82件を再実行するものでもありません。

`run-start.json` は実行前、`run-result.json` は終了時に別々に保存します。ログ、失敗、前後ハッシュ、検査器の生記録も残します。空のstderrだけでは成功にしません。成功には、指定版、固定バイト、通常経路の正常終了と全項目通過の一致が必要です。これは今回の環境確認の判定であり、003の四条件の改訂ではありません。

一時的なfixture用SQLiteは結果フォルダーに作ります。公式runのストアには書きません。ネットワークを止めるPython audit hookは、この点検経路の設定であり、特権的な迂回や一般的な安全性の証明ではありません。

検査が通っても、入力8,192トークン以下の根拠と、別の実行開始記録が残ります。準備評価全体、Stage 3、Stage 4の完了にはしません。条件版・結び付け版・001–003・Bundle・資料集は変更しません。

GitHubのソースから使う場合は、ZIP同梱の `targets/repo` の代わりに `--repo` で参照ルートを指定します。

```bat
"C:\実際の場所\Scripts\python.exe" -I -B -X utf8 run_environment_check.py --repo "C:\実際のリポジトリ"
```

`target-manifest.json` は必要な固定ファイルの部分集合、`tool-manifest.json` は新しい実行補助ファイルを特定します。ハッシュはバイトの照合用であり、実行や独立再現の証明ではありません。

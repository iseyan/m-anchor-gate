# M-Anchor Stage 3：決定論的ゲートの統合・再生評価

共有会話で収集済みの15件を変更・再生成せず、外部の検証処理を通して再生する Python アプリです。`Bundle_1.0.zip` の Python v0.1 コアと既存テストをそのまま保持し、外側にケース・参照版・参照ハッシュ・証拠のケース別受理・保存・監査を追加しています。

評価結果は [評価報告](evaluation-report.ja.md)、実行データは [results](results/) にあります。Python 3.11以上の標準ライブラリだけで実行でき、APIキーやネット接続、追加パッケージは不要です。

## 起動

このフォルダーで PowerShell を開きます。この作業環境では次だけで新しい評価結果を作成できます。

```powershell
.\run.ps1
```

別の環境では、Python 3.11以上を用意して次を実行します。既存の結果を上書きしないよう、新しい出力先を指定してください。

```powershell
python -X utf8 replay.py evaluate --out results/my-run
python -X utf8 restart_check.py --out results/my-restart
python -m unittest discover -s tests -v
python -m unittest discover -s vendor/python_v0.1 -v
```

このワークスペースで Python を直接指定する場合は、`python` を `..\..\work\.venv\Scripts\python.exe` に置き換えます。`run.ps1` はこの既存環境を優先して使用します。

## 提案を1件ずつ検査する

```powershell
python replay.py init --db local-state.sqlite3
python replay.py snapshot --db local-state.sqlite3 --case PI-09
python replay.py apply --db local-state.sqlite3 --case PI-09 --raw collected/raw/PI-09-T1.json
python replay.py snapshot --db local-state.sqlite3 --case PI-09
```

`init` は信頼された運用者だけが行う初期設定です。既存状態の初期化・上書きはできません。`--case` は呼び出し側が指定するケースで、モデルが返した `case_id` と一致する必要があります。`apply` は入力ファイルのバイト列をそのまま監査に残します。拒否も正常な検査結果として JSON を返し、起動・保存・設定エラーは終了コード2、評価の期待値不一致は1です。

再生評価では試行ごとに新しい独立ストアを使います。PI-09の3件を同じストアへ続けて投入すると、最初の更新後は参照版が古くなるため、2件目以降は拒否されます。これは独立試行の再生とは異なる操作です。

## 境界と保存

1. `collected/authority.json` は外部で固定したケース、初期状態、証拠受理、解釈規則です。モデル出力でこれらを追加・変更する経路はありません。
2. `gate.py` が構造、ケース、版、ハッシュ、証拠の登録・有効性・ケース別受理を検査します。解釈は外部に保存した完全一致の証拠集合から取得し、モデルの説明を使いません。
3. 同梱の公開コアへ、モデルが提案した候補集合を明示的に渡します。無効な提案を自動的に正しい候補へ修正しません。
4. 成功した候補更新と版・ハッシュ・監査を SQLite の同じトランザクションで保存します。競合時にも参照検査と更新を直列化します。
5. 拒否・読み取り・要約・実質的変更のない提案は、状態や版、ハッシュ、証拠権限を進めません。拒否の監査記録は残します。

`cause_status` の候補数による対応、版の増分、ケース別の完全採用要件は外側のアダプター規則です。PI-09では現在有効な受理済み証拠の全体を必要とし、`{h_A,h_B} ∩ M(e_B) = {h_B}` を要求します。コア自体が許す部分採用の一般的意味論は変えていません。

`H1` は元の試験の参照ラベルです。ストアは別の SHA-256 で内部整合性を検査し、実際に更新された状態には計算した新しいハッシュを付けます。ハッシュは署名や、ファイルを書き換えられる攻撃者への防御ではありません。

## 比較経路と評価範囲

`unchecked-evaluation-only/` は比較専用の別ストアです。提案の候補・状態・参照版・参照ハッシュを信用して採用し、版更新要求があれば提案の参照版に1を加えます。PI-04では候補に変化がなくても `7/H7` を採用します。したがってこれは参照検査・証拠受理・削除検査をまとめて外した比較であり、削除検査だけの効果を単独で測る試験ではありません。

各経路に同じ原文バイト列を渡します。期待結果は `manifest.json` に外部で固定し、判定ラベルだけでなく実際の保存状態、版、ハッシュ、他ケース、証拠権限、監査原文、再読み込みを照合します。実装と入力のハッシュも結果へ記録します。

`restart_check.py` は複数の独立した Python プロセスで初期化・検査・再読み込みを行います。このローカル実証と、元のPI-05の「新規モデルセッションによる再開模擬」は区別します。元の API リクエストと正本状態を結ぶ認証済み記録は、共有会話からは復元できません。

モデルにはこのストアのファイル、任意コード実行、初期設定機能を渡さない構成を前提とします。同一ユーザー権限でDBを直接編集できる攻撃者へのOSレベルの隔離・改ざん防止・本番アクセス制御を実証したものではありません。

## 元資料

- `vendor/python_v0.1/`：提供 ZIP 内のコア・既存テスト・README。実行時にコアのハッシュを固定照合します。
- `bundle-provenance.json`：ZIPと内部12ファイルの照合記録。Zenodo公開レコードとの独立照合は未実施です。
- `collected/raw/`：共有会話にユーザーが貼り付けた正式15件の JSON 部分。改行の追加や JSON の再整形をしていません。
- `collected/manifest.json`：試行ID、ケース、原文ハッシュ、外部期待値。
- `collected/provenance.json`：採取方法、除外試行、由来の限界。

[共有会話](https://chatgpt.com/share/6abb8a58-1f30-83e8-8c7f-b831d63fcbc7)の文章や過去の評価者の要約は、証拠受理を許可する入力として使いません。原文は貼り付けられた JSON の転記であり、元の API レスポンス全体のバイト列や実行IDを認証したものではありません。期待値を漏らした旧PI-04の試行は正式採点から除外し、確認できた旧T1の原文だけ別に保存しています。

## Agents API アプリとの関係

既に作成・実接続確認済みのアプリは隣の [m-anchor-agent](../m-anchor-agent/README.md) にあります。再利用可能な定義、セッション開始、出力とイベントの逐次受信、継続メッセージを扱います。

今回の再生はそのアプリでモデルを再呼び出ししません。Agents API側の `tools: []` を維持し、正本への書き込み機能をモデルへ追加していません。新しいモデル出力を検証する場合も、信頼された呼び出し側がケースと参照状態を固定し、得られた原文をこの検査経路に渡す必要があります。

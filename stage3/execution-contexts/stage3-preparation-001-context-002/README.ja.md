## トークン確認方法と呼出し上限

公式資料は、入力の構造に伴うトークンも含めた送信前計数に `POST /v1/responses/input_tokens` を示しています。[計数ガイド](https://developers.openai.com/api/docs/guides/token-counting)

この記録で確認した資料からは、固定モデルへの**要求全体**を保証できるオフライン上界は確立していません。文字数、UTF-8バイト数、可視テキストのトークン数へ根拠のない余裕を足して合格にはしません。

ただし、現行フォームの固定は `maximum_total_api_calls=7` で、予定生成も7回です。生成7回に計数7回を足せば全体は14回になります。したがって、計数APIを現行条件のまま追加することはできません。

`token-method.candidate.json` に、次の**未採用案**を具体化しました。

- 生成上限7回を維持する。
- 計数専用を各試行1回、最大7回とし、生成と別に記録する。
- 総呼出し上限14回への変更は別の条件改訂・実行結び付けで扱う。現在の上限は変更しない。
- 再試行・自動切替・追加生成は0回。失敗した計数も試行を消費し、再計数しない。
- 計数の料金・予算への組込みは未確認。無料とはみなさず、既存のUSD 1予算を増やさない。

これは採用決定でもAPI実行の許可でもありません。総呼出し7回を維持する場合、現時点ではトークンゲートを閉じられません。

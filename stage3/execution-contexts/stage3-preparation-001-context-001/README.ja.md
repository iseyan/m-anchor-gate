# 実行環境・料金・保存先の結線計画 001

固定した条件版と実装結び付け版を保ち、新コードを指定検証器で確認する手段を用意した記録です。Windowsでの確認と公式runは未実行です。`conditions_frozen=true`、`implementation_binding_frozen=true`、`execution_ready=false` を維持します。

| 項目 | この記録の状態 |
| --- | --- |
| 条件・Adapter・テンプレート・R4・評価器 | binding-001のハッシュを参照。変更なし |
| 実行環境 | 003で使ったvenvを既定にした確認キットを作成。現在の環境は未確認 |
| 新コードの外部検証器による確認 | 未完。Windowsの別実行記録を待つ |
| 公開料金 | 指定モデルの公式資料を再確認。固定料金と一致 |
| 入力8,192トークン以下の根拠 | 未解決。上界記録を発行していない |
| 保存先 | ローカル確認の新規出力を定義。公式runの物理ルートは未確定・未作成 |
| 呼び出し・段階 | モデルAPI 0、計数API 0。準備評価未完、Stage 4未開始 |

次の操作は [環境確認キット](../../../local-tools/stage3-environment-check-v0.1/README.ja.md) の実行です。結果はキットの外の新しいIDへ保存します。旧local-check-001やschema-gate-001–003を置き換えません。外部検証器の経路は68項目で、以前の69項目との差は構造確認専用の1項目です。003の82件とは別の検査です。

`pricing-check.json` は公開料金の照合です。入力 $0.75 / 100万トークン、出力 $4.50 / 100万トークンを確認し、固定上限での計算は1回 $0.01536、7回 $0.10752です。支出上限 $1.00、1回の予約 $0.02 は条件版を継承します。実行時には再確認が必要で、料金の保証や発生済み費用ではありません。アカウントでの利用可否は未確認です。[公式モデル資料](https://developers.openai.com/api/docs/models/gpt-5.4-mini)

`token-budget-method.json` では、公式の `POST /v1/responses/input_tokens` が入力構造分を含む計数方法であることを確認しました。ただし今回は呼びません。固定フォームは `maximum_total_api_calls=7` と書いているため、計数呼び出しを追加するなら、その数え方と実装を別版で先に固定する必要があります。文字数・UTF-8バイト数・根拠のない余裕分だけでは全入力の上界を認定しません。[公式計数資料](https://developers.openai.com/api/docs/guides/token-counting)

後続のR5入力は実際の保存状態で決まります。初期fixtureや模擬入力で得た値を流用せず、解決後の方式は各送信バイトのハッシュ、モデル、方法記録、上限へ結び付けます。この計画に `verified_host_token_bound` や `execution_ready=true` を追記しません。

`storage-map.json` はローカル結果と将来の公式runを分けています。公式runの論理パスは条件版を引き継ぎます。絶対保存先は別の開始記録で確定します。比較ストアは正本入力に使いません。

今回の判断は、実行できるローカル確認を先へ進め、根拠が未確定のトークン境界は未解決として残す、です。査読は参考資料であり、承認権限や追加の合格条件ではありません。仕様・条件版・結び付け版・001–003・Bundle・資料集・閉じた報告は動かしません。

配布と作成環境での確認は、同じディレクトリの `package-verification.json` と `checks/` に別記録で残します。これはWindowsでの実行結果でも、指定検証器による新コードの合格記録でもありません。

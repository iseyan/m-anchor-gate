## 3. ケースごとの証拠受理

e_Bは対照用の登録済み器具であり、現実の因果認定ではない。登録表とケース別受理表を区別する。以下は準備すべき条件であり、受理担当が実際に受理した記録ではない。

| 経路 | 実行前に用意するケースと根拠 |
| --- | --- |
| R1：証拠なし・対応B | K={h_A,h_B}、選択済みa_B、受理証拠なし、適用D=空。e_Bが登録済みでもこのケースでは使えない |
| R2：証拠の全反映 | 当該ケースに受理済み・有効なe_B。M({e_B})={h_B}。全反映要求と、妥当な更新の期待値は別管理 |
| R3：既存証拠の再利用 | 呼出し前から受理済み・有効なe_B。新規観察は空でも、適用D={e_B}を許す |
| R4：証拠資格の違反 | 対応ID、要約ID、未登録ID、登録済みだがケース未受理のe_B。各不正提案の実体・ハッシュ・出所を固定する |
| R5：再開と入力差分 | 基準、K差分、対応のみ差分、要約のみ差分を用意する。各状態の保存経路・版・証拠根拠を残し、実際の入力差分を記録する |

R2で両候補を残す出力は全反映要求の未達として数え、保存違反にしない。R4の固定再生は、モデルがその違反を出したという観測に加算しない。ケース未受理のe_Bは比較先でも拒否する。

## 4. 呼出しと再生の割付案

| 対象 | 初回案の内訳（正式値は未記入） |
| --- | --- |
| R1／R2／R3 | 各1モデル呼出し、計3。得られた同一提案を二つの独立ストアへ再生する。比較方式ごとにモデルを呼び直さない |
| R4 | 追加モデル呼出し0。未観測の違反型を固定不正提案で補う。最大4提案×2ストア。モデル生成と固定再生を分けて集計する |
| R5 | 基準と3差分を各1呼出し、計4。基準との3組を採点する。各回は新プロセス・新規要求。読取判断を更新提案として保存しない |
| 全体 | 合計7 API呼出し。自動・手動の再試行はともに0。失敗分を成功例で置換せず、修正・再実行は別の凍結票へ結ぶ |

API呼出し、ストア再生、検証器の処理を別に数える。全モデル提案が合法ならモデル出力の比較結果は差なしとして残す。固定再生の結果でそれを置き換えない。

## 6. 保存・停止・終了

全API要求・生応答・形式不正・拒否・タイムアウト・失敗・使用量を残す。記録には試行ID、提案ID、適用証拠、規則版、前後状態、拒否理由、時刻を含める。再試行を許す将来の票でも、初回を上書きしない。

検査付きの正式経路で保存違反、ケース未受理証拠の受理、正本への迂回書込が観測されたら、その版の進行を止める。失敗記録を保存した後、修正版と新しいrun IDへ結ぶ。検査なし比較先で意図的に観測する不正削除は比較結果として区別する。

準備評価の完了、企業側での工程3評価完了、採用判断を別欄にする。企業側の組織・実業務・既存方式・期間・採用条件は未選定のまま、企業評価の開始前に固定する。これらは今回の準備評価開始に先立つ必須選定とはしない。

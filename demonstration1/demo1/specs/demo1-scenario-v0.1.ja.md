# 工程2：実証1号の場面固定

原因A/B未決、対応B、要約、再開、保存した区別に基づく判断

場面仕様 v0.1  |  2026-09-29 (JST)  |  iseyan

基準は「実証1号の保証範囲と成功条件 v0.1」。本書は③の主場面の入力・順序・記録を固定する。既存の①保存、②拒否と記録、④証拠あり対照も維持する。実装前の予定仕様であり、実行結果ではない。

**固定する判定文：既存仕様③のまま**

> a_Bは選択済み／原因A・Bは未決

## 固定する主場面

| 手順 | 固定内容 |
| --- | --- |
| 1  初期状態 | ケースIDは demo1-main。状態版0、K = {h_A, h_B}、適用証拠Dは空。h_Aとh_Bは架空の障害原因A/Bを表す。この主場面では証拠を追加しない。 |
| 2  対応Bと保存 | 二値出力B（対応 a_B）を固定入力とし、選択理由は提出手続上の暫定選択とする。候補更新を検査し、K = {h_A, h_B} と空の証拠根拠、監査記録を保存する。状態版1と対応記録 action-001 を対応づける。 |
| 3  要約 | 要約文は「暫定対応Bを選択した。」に固定する。対応選択だけを記した要約として保存し、証拠として採用しない。正式なKと状態版1は変えない。 |
| 4  終了と再開 | 保存完了後に前のプロセスを正常終了する。別プロセスに渡すのはケースIDと保存先だけとし、要約、正式な状態版1、対応記録 action-001 を読み出させる。前のプロセスのメモリは引き継がない。 |
| 5  判断と記録 | 読み取ったKと対応記録に基づき、上の固定判定文を出す。どのプロセスがどの版・候補・対応を読み、その区別を判断に使ったかを、一続きの記録として残す。 |

状態版は検査済み保存の識別子。候補が同じでも手順2で0から1へ進め、要約保存・読出しでは進めない。

## 再開時の記録に対応づける値（予定値）

| 項目 | 予定値・記録方法 |
| --- | --- |
| 読取元 | case_id = demo1-main ／ state_version_read = 1 |
| 読取内容 | K_read = {h_A, h_B} ／ evidence_basis = [] |
| 対応記録 | action_record_id = action-001 ／ selected_action = a_B |
| 判断への接続 | 上の判定文と、使用した状態版1・対応記録を同じ判断記録に結ぶ。書込側と再開側のプロセス識別子は、実行時の値を記録する。 |

## 合格判定の適用

要約だけからKを復元せず、状態版1の両候補と対応記録を読んで判断したことを追える場合に、既存③を満たす。ファイル残留や判定文の一致だけでは成功扱いにしない。期待値は採点側が照合し、再開処理の入力には渡さない。

主場面の固定は以上とし、保証の核・対象外・他の合格条件は基準仕様を継承する。実装や試験実施は次の作業として別に記録する。
